# MouseCursorDetector 版本迭代

用中文沟通。先读取项目根目录的 [AGENTS.md](../../../AGENTS.md)，遵守用户当次范围及已经确认的授权。本技能仅用于所在项目，不安装为全局规则。

## 已确认的执行范围

- 用户要求“升级版本”“准备发布”时，分析变更并更新本地版本定义与变更记录；已授权的常规升版不重复询问相同规则。
- 用户只问“应该升什么版本”时，只分析与建议。普通功能开发、修复、文档编辑或 Git 同步不自动改变软件版本。
- 提交、推送、创建标签和 GitHub Release 分别沿用其明确授权；升版本身不授权这些操作。需要提交或同步时使用本机可用的 `github-sync`，它仅本地保留且不负责 Release；其他检出中缺少它时，按项目 `AGENTS.md` 及当次授权处理 Git，不把该本地技能补传至远端。
- 构建仍只能由用户手动执行；不运行 CMake、编译器、链接器、资源编译器、安装器编译器或间接调用它们的脚本，不擅自启动 EXE 或安装包。
- 创建或维护本技能不触发软件升版。技能创建时的软件基线为 `0.1.0`，以后每次执行必须重新核实，不将这个起点当作永久当前版本。

## 版本规则

采用 [SemVer 2.0.0](https://semver.org/lang/zh-CN/)。正式版本使用 `MAJOR.MINOR.PATCH`，三个字段均为无前导零的非负整数。标签和界面可显示 `v1.2.3`，其中 `v` 不属于版本号本体。

本项目以已文档化的用户操作行为、配置读取及迁移、目录约定、命令行参数和支持平台作为兼容性判断范围。配色、布局或文案变化本身不自动等于不兼容变更。

| 变更类型 | `1.0.0` 及以后 | `0.x` 阶段的项目约定 |
| --- | --- | --- |
| 保持兼容的问题修复 | PATCH 加一 | PATCH 加一 |
| 保持兼容的新功能 | MINOR 加一，PATCH 归零 | MINOR 加一，PATCH 归零 |
| 公开功能标记弃用 | MINOR 加一，PATCH 归零 | MINOR 加一，PATCH 归零 |
| 不兼容变更 | MAJOR 加一，MINOR、PATCH 归零 | MINOR 加一，PATCH 归零，明确记录兼容性影响 |
| 纯文档、截图、技能或不改变行为的整理 | 默认不升软件版本 | 默认不升软件版本 |

`0.x` 阶段的增幅是用户确认的项目政策；SemVer 本身不保证该阶段的接口稳定。不因一次不兼容变更自动宣布 `1.0.0`，进入稳定版本由用户决定。

同一发布包含多类改动时，取需要的最高增幅，只递增一次；依据实际变更判断，不仅按提交消息的 `feat` / `fix` 前缀计数。用户指定目标版本时先校验合法性、递增关系和是否已经发布，不静默改成另一个版本。未指定时说明判断依据后，按既有升版授权执行。

### 先行版本和构建元数据

- 需要测试版本时使用 `X.Y.Z-alpha.1`、`X.Y.Z-beta.1`、`X.Y.Z-rc.1`；同一阶段继续迭代时递增序号，切换阶段从 `.1` 开始。阶段名及序号是本项目的惯例，遵循 SemVer 的标识符语法。
- 先确定下一目标版本，再追加先行标识。`0.2.0-beta.2` 转正式版为 `0.2.0`，不额外增加 PATCH；不能在已发布的 `0.2.0` 后把 `0.2.0-rc.1` 当作更高版本。
- 核心数字与纯数字先行标识禁止前导零；`beta.10` 按数值排在 `beta.2` 之后。同核心版本下，先行版本低于正式版本。
- 用户有需要时才使用 `+build.123` 等构建元数据；元数据不参与版本优先级比较，不用它代替真实版本递增或重新发布已存在版本。
- 已发布版本、标签及其产物保持不可变；修正已发布软件时使用新版本，不覆盖旧版本内容。

## 分析当前版本和发布范围

1. 从本技能目录定位项目根目录；Git 查询显式指定该目录，核实它是独立仓库，读取当前分支、工作区和待发布改动。
2. 交叉核对源码版本、现有发布说明和相关标签。需要确认远端发布事实时进行必要的只读查询；本地没有标签不代表远端没有发布。不能访问远端时说明信息边界，不猜测“最新版本”。
3. 以目标发布线最近已确认的发布为基线，查看到当前目标源码的实际差异，包含当次范围内未提交改动。若相同版本已在工作区准备，继续完成该目标，不因再次调用技能重复递增。
4. 区分源码目标版本、已发布版本与当前 EXE 的嵌入版本。已有定义冲突时列出差异并查明原因，不盲选数值最大者，不把已知旧二进制当作源码冲突。
5. 给出“基线 → 目标、增幅理由、受影响文件、兼容性影响”。只对仍需用户决定的分支提问，沿用已经确认的规则。

## 本项目需要同步的位置

版本尚未集中生成。执行时重新搜索实际文件，按字段修改，不能全仓库替换所有旧版本数字。

| 文件 | 软件版本位置与处理方式 |
| --- | --- |
| `CMakeLists.txt` | `project(MouseCursorDetector VERSION X.Y.Z ...)`，作为数值基准；修改它不会自动更新下面的资源或文案 |
| `src/mouse_cursor_detector/resources/app.rc` | 数字 `FILEVERSION`、`PRODUCTVERSION` 写为 `X,Y,Z,0`；可读 `FileVersion` 字符串使用完整软件版本并保留 `\0` 终止符 |
| `src/mouse_cursor_detector/resources/app.manifest` | 仅应用自身 `assemblyIdentity` 的版本写为 `X.Y.Z.0` |
| `src/mouse_cursor_detector/app.cc` | “关于”窗口的软件版本文字 |
| `src/mouse_cursor_detector/settings/localization.cc` | 与“关于”文案匹配的中文翻译键及英文值；必须同 `app.cc` 一起更新，避免字符串匹配失效 |
| `src/mouse_cursor_detector/settings/settings_themes.cc` | 侧栏显示的 `vX.Y.Z` 或完整先行版本 |
| `installer/MouseCursorDetector.iss` | 当前 `AppVersion` 从 `AppExe` 的 PE 数字版本读取；通常无需另写一个固定版本，不修改 `AppId` 或互斥体身份 |
| `docs/releases/v版本号.md` | 为目标版本新增或更新未发布草稿，保留旧版发布说明的历史事实 |
| `README.md` | 在新版实际发布且下载可用后更新当前下载链接；源码升版准备期间保留现有可用下载入口 |

### 数字字段与先行版本的差异

[CMake 的 VERSION](https://cmake.org/cmake/help/latest/command/project.html#options) 仅接受数字分段；[Windows VERSIONINFO](https://learn.microsoft.com/en-us/windows/win32/menurc/versioninfo-resource) 的数字版本由四个 16 位整数组成。CMake 保留 `X.Y.Z`，Windows 数字资源及应用清单保留 `X.Y.Z.0`，不能把 `-rc.1` 或 `+build.123` 塞进这些数字字段；数字超出 Windows 字段容量时报告限制，不能截断或取模。

完整先行版本保留在可读字符串、界面和发布说明中。当前安装器从数字版本读值，会丢失先行标识，不能宣称安装器已能区分 alpha / beta / rc 的显示和升级顺序；如任务要求这种区别，需要在该任务范围内处理安装器显示与升级映射，不能自行发明第四段编号。获得发布授权后，先行版 Release 应标记为预发布。

### 不随软件升版修改的数字

- `portable_settings.cc` 的 JSON schema 版本及对应示例、兼容读取规则；`settings_store.cc` 的旧注册表记录布局版本。
- 单实例互斥体的 `.v1` 后缀，以及安装器用来识别同一软件的 `AppId`。
- 清单 schema、Common Controls 依赖版本、CMakePresets / VS Code 配置格式版本。
- CMake 最低版本、C++ 标准、Windows 最低版本、Inno Setup 或工具链版本。

这些内容仅在另有明确功能或迁移需求时修改；不因软件版本数字相似就一起更新。

## 变更记录、验证与交付

- 沿用 `docs/releases/`，按实际变更写新增、改进、修复、兼容性影响和验证状态；不创建空分类，不把每条提交原样拼接为发布说明。已有 CHANGELOG 时与目标版本保持一致，没有时不强制新增另一套记录。
- 准备阶段明确写“待发布”，不预填已经发布的日期，不编造新 EXE 的大小、哈希或验收结果，不改写旧版说明及旧截图来假装属于新版。
- 只做允许的静态核对：版本字段一致性、中文翻译键对应、JSON / XML / PowerShell 语法，以及改动涉及的格式检查。不能用配置或试编译验证版本。
- 源码升版不会改变现有根目录 EXE。保留旧产物，报告它们仍是旧版本；由用户手动执行下列命令构建和打包：

  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
  ```

- 用户完成构建后可只读核验应用 PE 数字版本、安装包产品版本及 SHA-256。字符串字段先去除首尾空白；安装包可能没有有效 `FileVersion`，应用也可能没有 `ProductVersion` 字符串，不因空字段捏造版本。版本、哈希和时间戳均不能单独证明源码与产物严格对应或交互验收通过。
- 实际发布前核对目标源码、发布标签、用户构建的应用与安装包、发布说明和校验值一致，并保留可追溯的构建及验收信息。不将旧 EXE 冒充目标版本上传，不通过重打已发布标签掩盖不一致；已授权的其他准备工作继续完成。
- 最终报告目标版本、判断依据、修改范围、静态检查结果及源码 / 产物 / 发布各自状态。仅分析、源码准备、已构建、已验收、已提交和已发布必须据实区分；只维护本技能时无需构建软件。
