# Ant Design 控件来源约束

本 skill 仅用于 MouseCursorDetector。用户已授权在 C++/Win32 中按官方描述进行原生适配；必须明确标注“Ant Design 规范的 Win32 原生适配”，不得声称运行的是 Ant Design React 组件。创建或调用 skill 本身不代表要求立即重写项目界面。

## 来源与范围

- 指定官网入口：https://ant.design/components/overview-cn/ 。每次控件变更任务都读取当前总览及左侧组件分类列表；总览正文卡片不是唯一组件发现范围。
- 允许读取总览及其官方子页面中所有控件的 `LLMs.md` 说明，包括左侧各分类列出的组件，以及沿官方组件文档可追溯到的下级组件、子组件、组合形式、状态和变体。允许读取全部文档，不代表每次任务都必须全量读取；本次涉及的组件及依赖文档必须完整阅读。
- 具体涉及某个组件时，必须从左侧列表的对应分类和组件选项进入官方页面，在该页面选择符合需求的组件、子组件或变体，再读取其 `LLMs.md`。记录“总览 → 左侧分类 → 组件页面 → 子组件/变体 → LLMs.md”的来源链；不能只凭总览卡片、搜索结果、组件名称或记忆确定选型。
- 总览或官方组件文档明确链接的官方组件系列也在范围内，须沿该系列的官方分类与组件页面核实具体控件及文档；一个生态网站的链接不等于该网站所有内容都已获准。
- 左侧组件分类导航是有效的选取入口；其他全站导航、页脚、广告、任意外链、第三方封装或设计师自创控件不作为组件来源。不把 `llms.txt` 中的工具、变更日志等所有条目当作组件白名单。
- 本次任务范围内的控件须全部映射到官方组件或官方组合形式，不保留无来源的自制替代。多个官方组件可以按官方示例组合，不能自行混搭出不同的格式排版。未涉及的页面不因本 skill 自动扩大修改范围。
- 不维护冻结的分类或组件清单；以实际读取的官方总览、左侧分类列表和组件文档为准。

## 每次修改前读取 LLMs.md

1. 明确本次涉及的每个控件，从总览或官方子页面左侧组件列表的对应分类进入组件页面，确定目标官方组件、具体变体与示例。先完成来源核实和文档阅读，再修改显示代码；已存在的控件也不豁免。
2. 在经左侧分类列表选取的组件官方页面中，取得标注为 `LLMs.md` 的真实链接并读取正文。该标签不代表文件名一定叫 `LLMs.md`；例如 Button 中文页面对应 `https://ant.design/components/button-cn.md`。
3. 文档发现可使用官方说明 `https://ant.design/docs/react/llms-cn/` 和导航 `https://ant.design/llms.txt`。它们仅帮助定位，不能代替目标组件文档。不要只根据组件名猜测链接，尤其是外部官方系列和子组件。
4. 阅读目标组件的用途、完整相关 API、尺寸参数、状态、事件、交互和适用示例。子组件或变体若有独立 LLMs.md，另行读取；若在父组件文档中定义，读取对应完整章节。Markdown 只引用示例源码时，继续读取官方链接指向的示例；需要确认结构时再读取组件的官方语义文档。
5. 每个独立控件修改批次重新核实来源并读取所用文档；同一批次内已完整读取且没有变化的文档可以复用。不得用上一会话的记忆、搜索摘要、HTTP 成功状态或页面标题冒充正文阅读。
6. 浏览工具不支持 Markdown 内容类型时，可用可用的 HTTP 读取工具获取同一官方 URL 正文，例如 PowerShell `Invoke-WebRequest`。若仍无法读取、没有对应官方 LLM 文档或无法证明来源，停止该控件改动，报告具体缺口。聚合文档和截图不得冒充组件的 LLMs.md。

## 官方格式排版与尺寸边界

- 为每个控件明确一个官方变体或示例作为基准，严格遵循其描述、结构、内容顺序、对齐、分组、间距关系、状态与交互语义。不自行重排、简化结构或另行设计样式。
- 仅允许调整尺寸参数：官方公开的 `size` 等尺寸选项，以及适应窗口所必需的宽、高和等比例 DPI 换算。尺寸调整仍须符合官方描述，不能借尺寸之名改变排版关系或造成裁切。
- 不擅改字体、颜色、边框、圆角、图标形式、间距规则、控件内部排列、动画或状态样式；不通过自绘、样式覆盖或包装绕过此约束。需要不同表现时选择官方已有形式并先阅读其文档。
- 原生适配只承担显示、布局和必要的事件转接，复用项目现有 Win32 绘制、主题与 DPI 抽象。不得修改官方组件源码或示例的实际交互逻辑；原生实现要保持文档规定的可观察行为，并诚实列出不能等价实现的部分。
- 无法同时满足官方排版、原生控件语义或项目既有硬性约束时，暂停受影响控件并说明冲突，不自行放宽规则。不得因此引入 React、WebView、新框架、第三方运行库或辅助程序。

## 业务实现与页面显示严格分离

先阅读现有控件创建、绘制、布局、事件分发与其调用的业务入口，列出“现有控件 → 官方组件/变体 → 原生适配位置 → 原有业务入口”的映射，再实施显示替换。

- 项目已有业务核心代码及实现逻辑保持原样：算法、条件分支、状态转换、校验、默认值、数据模型、持久化、文件与注册表操作、快捷键、时序、线程和副作用均不得借控件替换修改或重构。
- 只修改页面显示层与必要的事件绑定。适配器调用原有业务入口，保留事件触发条件、调用顺序、次数、参数含义和错误处理；不得在显示层复制、重写或搬迁业务逻辑。
- UI 与业务位于同一文件时，按函数和代码段界定边界；文件位于 `settings/` 不代表整文件都可修改。只做必要的显示层局部修改，不趁机抽取或整理业务代码。
- 保留 Tab、Enter、Space、IME、选择、剪贴板、焦点和禁用状态语义；保留四套主题与 DPI 能力。若官方控件与既有业务行为无法直接兼容，报告差异，等待用户决定，不自行修改业务来迎合控件。
- 用户另行提出业务改动时，将其作为独立需求明确处理，不把控件任务解释为业务修改授权。

## 验证与交付

- 对照最终差异确认：所有涉及控件都有从左侧分类列表进入组件页面的来源链；每个目标文档正文已读；采用的变体、排版和尺寸调整有依据；业务核心实现未改动。
- 交付时简述组件/变体、原生适配方式、阅读的官方文档 URL、尺寸调整、显示层文件与保留的业务入口；如有未完成项，明确报告。
- 遵守项目 AGENTS.md：助手不得编译、链接、打包、安装或启动产物，不修改系统光标，不接触用户运行数据。修改源码后的验证以允许的静态审阅为限，明确说明尚未编译、尚未运行验证，并提供用户手动构建命令和重点验收项。
